# CLAUDE.md – anonymizePDF

Technical description of the project for maintenance with Claude Code. User-facing documentation: `README.md`.
Repo: `C:\Users\Lucas\Project\anonymizePDF` (Windows 10, Git Bash + PowerShell). The user writes in French or English.

## 1. Goal and constraints

- Anonymize PDFs (a few dozen, grouped in **client folders** of 3–5 PDFs) **fully locally**, through a small web app.
- Documents: mostly French, also Belgian / Dutch. Bank statements, contracts, invoices, identity documents
  (passport, ID card). Some are digital PDFs (text layer), some are scans.
- Personal data is **replaced by plausible fake values** of the same length / format, consistent across files.
  Not meant to produce perfect forgeries. What cannot be faked (photos, signatures, QR codes) is **blacked out and
  removed from the file**.
- One reviewable YAML config per folder (`anon_config.yaml`): generated by a scan, edited by the user, then applied.
- **Production PC has no admin rights**: everything must work with pip packages only (hence Windows OCR via
  `winrt`, fonts found through the registry, no system installs required). Python 3.12 / 3.13.
- Server on `127.0.0.1` only, confined to `--root` (path traversal -> 403). Originals are never modified; output is
  `<name>_anonymized.pdf` next to them.

## 2. Rules to keep

- Never commit real PDFs, `anon_config.yaml`, `anon_report.json`, `*_anonymized.pdf` (`.gitignore` covers them;
  `sample_data/` only contains generated fake documents).
- Never commit or share the secret key (`secret.key`); never put a constant salt / key back in the code.
- Never ask for or open real client documents; use / extend the generated test documents instead.
- Privacy first: when in doubt, cover more (over-redaction) rather than leak. A black box must remove the data from
  the file, not only hide it.
- Keep the scope small, no build step for the frontend, no new heavy dependency (no OpenCV / scipy / PyTorch:
  image analysis is done with numpy + Pillow). The one exception: onnxruntime (CPU, face detection), offline with its
  model file in the repo.
- Commit only when the user asks; commit messages end with the attribution line given in the session.

## 5. Pipeline

0. **Per page** (`page_layout`): a page is `scan` if it has fewer than 3 VISIBLE words (`pii.visible_words`:
   text with render mode 3 or opacity 0 – the OCR layer of a searchable scan – does not count), else `digital`;
   a digital page whose images cover >= 2 % of it also has `pixels` (OCR of what the visible text layer does not
   cover, `_pixel_words`). File mode in the report: digital / scan / mixed, plus `page_modes`.
1. **Scan** (`scan_folder`): per page, `_detect_words` on the text layer (digital), on the OCR (scan pages; the
   invisible layer of a searchable scan is read too) and on the OCR of the images (pixels). `fix_digits` on OCR
   text, `detect_all` (structured detectors + NER, line by line) and `_add_labeled` (identity fields by position). Aggregate by (type, normalized value). Persons: full names first,
   names with an initial last, plus their parts (≥ 4 letters). Generate fakes (`Faker.suggest` / `person`), align
   numbers contained in longer ones (`_align_contained_numbers`), drop commented suggestions that duplicate an active
   value, write `anon_config.yaml` (`render_config`). `faker.reserve()` gets every original value first, so no fake
   is a word of the documents and no two names share a fake (with some keys 'Thomas' became 'Julien', the real first
   name of someone else in the same statement).
2. **Review**: user edits the YAML (Config tab). `parse_config` validates it.
3. **Anonymize** (`run_anonymize`): every entry is a literal `find → replace` term (plus optional regex).
   - Only scan pages → `_scan_pdf` (a brand new PDF of images). Otherwise `_digital`, page by page:
     scan pages are rebuilt with `_scan_page` and replace the original page (delete + new page with the image);
     digital pages: `plan_page` → read fonts first (`page_spans`), redact matched words (graphics kept; matches in
     invisible text are removed without a fake on top), write the fake with `insert_replacement` (same font / size /
     colour / baseline); then `_pixel_pass` if the page has images (OCR minus visible text, redaction with
     `images=2` and the sampled paper colour, fake written as Helvetica text sized on the ink height, MRZ in an
     image rebuilt in Courier); then black boxes (`render.black_out_digital`). Finally annotations deleted,
     bookmarks / metadata / XML metadata wiped, `scrub`, `garbage=4`.
   - Scan page (`_scan_page`): render 300 dpi, OCR, OCR-tolerant matching. Before painting: MRZ zone, photos (if ID page or
     option), QR codes, signatures (excluding MRZ / photos / codes), ink colour, free space, bold. Paint each match with
     the sampled paper colour, write the fake (`scan_text_layout`), rebuild the MRZ, draw black boxes; the page is
     saved as a new JPEG in a new PDF (nothing of the original file is copied).
   - Verify (`verify_output`): searches the output for each original value (metadata, text layer, and OCR with the
     tolerant regex whenever the file is not purely digital, or when "OCR check" is ticked).
   - Report `anon_report.json` per file: mode, pages, replaced, seconds, items, leftovers, warnings,
     `blackouts: [{page, kind, box (PDF points)}]`, `mrz: [{page, action, format, lines}]`.

## 6. Config format (`anon_config.yaml`)

```yaml
ocr_lang: "fra+eng"
case_sensitive: false
match_case: true                    # UPPER / lower / Title case of the original applied to the fake
style: {mode: replace, digital_fill: none}   # mode: replace | blackbox ; digital_fill: none | white
blackout: {photos: true, photos_only_on_id_documents: false, signatures: true, qr_codes: true}   # photos = faces
mrz: regenerate                     # regenerate | keep   (old value 'blackout' is read as regenerate)
replacements:
  - {find: "Thomas Marchand", replace: "Alexis Beaumont", type: PERSON}
  # - {find: "30/09/2024", replace: "22/03/2025", type: DATE}   # commented = not replaced
regex: []                           # - {pattern: '...', replace: '...'}
```
Missing keys in older configs get the safe defaults (everything on). `find` matching (`pii.term_regex`): case-
insensitive, flexible whitespace, word boundaries; on scans `ocr=True` also accepts 0/O/D, 1/l/I, 5/S, 8/B, 2/Z,
missing accents and a space inside a number. Overlaps: longer match wins, terms beat regex.

## 7. Detection (`pii.py`, `fields.py`)

- Types: IBAN (mod-97), BIC, EMAIL, PHONE (BE/FR/intl), CREDIT_CARD (Luhn), CARD_NUMBER (masked `6703 **** **** 4471`,
  `Carte x4412`), BE_NATIONAL_NUMBER, BE_VAT, BE_STRUCTURED_COMM, SEPA_CREDITOR_ID (checksum, or after a label),
  STREET_ADDRESS, POSTAL_CITY, ACCOUNT_NUMBER (after "N° de compte" / "Numéro client", French RIB, long digit runs),
  BANK_CODE ("Code banque / guichet", "Clé RIB"), CONTRACT_REF ("police", "contrat", "dossier"), DOC_NUMBER,
  BIRTH_PLACE, DATE (`/ . -` or spaces `14 05 1992`), PERSON, NER ORG / LOCATION (always commented out).
- Page text normalises Unicode dashes (U+2010…) to `-` one-for-one (`words_to_text`), so spans stay valid. A real
  PDF used U+2010 inside a national number and hid it from every detector.
- Split types: groups of ≥ 5 digits of ACCOUNT_NUMBER / BANK_CODE and ≥ 4 digits of masked CARD_NUMBER are also
  separate entries (OCR may drop the stars); digit groups get the same fake everywhere (`Faker.digit_groups`).
- Dates are active only for birth dates (`_BIRTH_RX` within 35 chars before / 8 after, or a birth-date label).
- PERSON: after a title, `Prénom NOM`, `NOM Prénom`, spaCy PERSON; active only if after a title, contains a known
  first name, spaCy Title Case, or found under a label. `_STOP` words (including label words such as signature, nom,
  nationalité, adresse) are never names.
- Identity fields (`fields.find_labeled`): label lines (FR/EN/NL; OCR reads `/` as `I`, `°` as `'`) and the value
  line right below (left-aligned, within ~2 line heights) or after `:`. Kinds: surname, given, birth_date,
  birth_place, doc_number, sex, expiry, issue, country, address (several tight lines). `is_id_document`: MRZ found,
  ≥ 2 identity labels, or a keyword (passeport, carte nationale d'identité, permis de conduire, ...).

## 8. Fake values (`fake.py`, `secret.py`)

- Deterministic for a key: `HMAC-SHA256(key, variant|kind|normalized value)`. The 256-bit key is created once per PC
  (`%APPDATA%\anonymizePDF\secret.key`, `ANON_SECRET_FILE` overrides, `O_EXCL` creation, corrupt file → error, never
  silently replaced). Same key → same fakes in every folder. A constant salt allowed a dictionary attack (fixed).
- Names: FR/BE/NL lists by length and **gender** (`gender_of`: lists, then the title, then French endings; the
  `Sexe` field wins on ID documents). Keys without case / accents (`_pkey`: `Élodie` = `elodie`, used in e-mails).
  `Faker.names` memory keeps consistency: initials follow the replaced first name (`initial`, preferring first names
  seen with the same surname), names ≥ 80–85 % similar (OCR misreading) reuse the replacement (`_similar_name`).
  A replacement can never be the original without accents (`Inès` ≠ `Ines`).
- Other types: phone keeps format + first 2 digits; IBAN country / grouping, valid checksum; BIC keeps country;
  e-mail keeps common domains; streets from lists (article + noun replaced together, people-like names for long
  ones), towns matching the postcode's country; dates shift (same fake whatever the separator); BE national number
  uses the fake birth date of the same person + valid check digits; SEPA creditor id valid; doc numbers keep their
  letter / digit pattern; masks (`****`, `x`) kept.
- `match_case` (engine) applies UPPER / lower / Title case of the matched text.

## 9. OCR (`ocr.py`)

- `engine()`: Tesseract if found (TESSERACT_CMD, PATH, Program Files, %LOCALAPPDATA%\Programs), else Windows OCR
  (`winrt-Windows.Media.Ocr`, one language: the first of `ocr_lang` installed in Windows). `pip install tesseract`
  is an unrelated package.
- Windows OCR quirks: ~1 s/page, reads some `0` as `O` (handled by `fix_digits` + tolerant matching), drops isolated
  letters (the `F` of Sexe) and sometimes whole labels, reads only part of a passport MRZ line 1 and none of an ID
  card MRZ, even on cropped / enlarged lines.
- Tesseract: two passes (`--psm 3`, then `--psm 6` split at column gaps), best reading kept per line.

## 10. Rendering

- Digital (`insert_replacement`): font = the embedded font if it has every glyph, else the same font installed on
  the PC (Windows registry HKLM + HKCU, no admin: e.g. Consolas → consola.ttf), else the closest base-14. Same size,
  colour, baseline; may extend up to +35 % into free space (`free_right`), else shrunk. `digital_fill: none` keeps
  the page background (redaction with `fill=False`).
- Scans: text sized from the ink height of the original (tight OCR boxes), same baseline, ink colour sampled, paper
  colour sampled for the patch. Bold (`BoldMeter`): median horizontal ink run / estimated font size vs the page
  median, bold if > 1.4× (calibrated against Test 1's digital twin). Fails on ID documents (mostly bold text, no
  regular reference). Font: Arial / Arial Bold.
- MRZ (`draw_mrz`): OCR-B if installed, else Consolas. The character advance comes from the OCR box of the chevron
  line (`find_mrz`, not from the ink of the page: a card edge next to the MRZ made the text too wide). The old text is
  erased pixel by pixel (`_erase_ink`: dark pixels take the local paper colour), never with a flat rectangle, then the
  new lines are written with the same ink colour.

## 11. Identity documents: MRZ, photos, QR codes, signatures

- **MRZ** is never read back and never blacked out: always rebuilt in the same format (`mrz: keep` to leave it).
  `find_mrz`: a line with ≥ 4 chevrons from OCR, else `_mrz_by_image` (2–3 unread bands, same height / start / pitch,
  ≥ 19 evenly spaced characters). Other lines above / below must look like MRZ too (`_mrz_like`). Format: 3 lines →
  TD1 (3×30); `P` or > 40 chars → TD3 (2×44); `IDFRA` → FR_ID (old French card 2×36); else TD2 (2×36).
  `_new_mrz`: page fields after replacement (`_fake_text`), doc code / country from the OCR'd first line, names fall
  back on the config's PERSON replacements, missing values random of the right shape; check digits always valid.
- **Faces** (`faces.py`, replaces the old photo heuristic, which was calibrated in mm on flatbed scans and failed on
  photos of cards on a table): YuNet face detector (ONNX Runtime, CPU, offline; the model file is in
  `anonymizer/models/`, its sha256 is checked before loading). Runs on the whole image at 640 px, at 1280 px and at
  full size (windows of 640 px, 75 % overlap) and on the three quarter turns for the coarse scales, merged by NMS
  (score ≥ 0.6). The box is widened to the whole head (+20 % sides, +35 % hair above, +15 % chin). Digital pages are
  rendered at 150 dpi and searched the same way. Kind in the report: `photo`. Searched on every page unless
  `photos_only_on_id_documents: true`. Limits: frontal model (profiles can be missed), no face on a document
  that is far below ~25 px.
- **QR / 2D codes** (`find_codes`, 100 dpi): dark modules merged by closings of 3 / 5 / 7 px into a mostly solid square
  7–60 mm; accepted if fine checkerboard (density 0.3–0.75, ≥ 0.45 transitions / mm both ways) or structured
  (`_code_structure`: QR finder squares in ≥ 2 corners, or Data Matrix solid left + bottom edges). Digital pages are
  rendered at 150 dpi and searched the same way (image and vector codes).
- **Signatures**: `is_signature_label` (signature / handtekening / unterschrift among the first two words of the line,
  or a line of ≤ 4 words — not a sentence; `firma` was dropped: it means "company" in NL/DE). Ink not OCR text of
  normal height, not a ruled line, not in MRZ / photos (the face area widened by 50 %) / codes; seeded next to the
  label, grown through strokes ≤ 3 mm apart (`_grow`) in a window of 12 mm above / below the label and 5 / 80 mm
  around it. Components that are solid (fill ≥ 0.4) or lie mostly inside an OCR word box are print, not ink.
  The label is spared only if the strokes do not touch it. Digital: drawings / images grown the same way.
  A box never covers an OCR word: it is cut on the side that keeps the most dark (signature) pixels and still holds
  the middle of the label (`_clear_of_text`, `ink_mass`). Known limit: a signature on a card whose guilloche is
  connected to it gives a wide box (Reel "Lucas Jacquemin Id Cards": 62 x 12 mm, lower part of the card).
- **Slanted text** (`regions.text_angle`, `line_angles`): skew by projection profile (-20..20 degrees, fine step).
  Lines of ≥ 1.5 degrees are painted turned: the patch is turned straight, erased and written there, turned back, and
  only the changed pixels are pasted back. A line with an unreliable measure takes the common slant of the page.
- **Removal guarantee** (verified by extracting the output objects): scans are rebuilt from one new image per page.
  Digital: `black_out_digital` redacts with `images=2, graphics=2` (text removed, covered pixels overwritten, fully
  covered images and their SMask dropped, touched drawings removed — MuPDF's "remove if covered" mode keeps
  strokes, i.e. signatures), redraws the collateral lines that are not inside a box (frames, table borders) from
  `get_drawings()`, then paints the boxes again on top.

## 12. Test suite: `python tools/check_all.py`

Run it after every change (exit code 0 = all passed; ~3 min with 2 keys, `--quick` = 1 key and no option tests,
`--folder "Dossier Test 4"` to target, `--keep` to keep outputs). It copies `sample_data/*` to a temp dir and uses
temporary random keys (`ANON_SECRET_FILE`), never the user's key, never writing into `sample_data/`.
- Per output file: no error; expected mode (digital / scan / mixed); **leaks** in the text layer, a fresh OCR of every
  page and the metadata (names as whole words, numbers / multi-word values as substrings, accent-insensitive);
  report leftovers empty; expected black-box kinds, each black in the rendering; nothing under a box in digital
  outputs (no text, no drawing but the box, no original image); no original image at all in scan outputs; MRZ
  format, lengths, check digits, fake surname inside.
- Expectations per file are in `EXPECT` (sensitive values written by the generators, mode, box kinds, MRZ formats).
  A new test document needs an entry there.
- Secret key and fake values: key creation / reuse / corrupt file, determinism, gender, initials, e-mails, OCR
  misreadings, never the original without accents, a wrong key does not single out the true name.
- Options: qr_codes / signatures off, `mrz: keep`, old `mrz: blackout`, photos searched on every page of statements.
- Several keys matter: some bugs only appear with some keys (`Inès` → `Ines`, `Thomas` → `Julien`).
- UI changes: check in the Browser pane (it may be hidden: rAF and scroll events then do not fire).

## 13. Known limits / ideas

- Scans depend on OCR quality; names are heuristic (review step). Leftover check only knows the config's values.
- Slanted text (scans, photos): OCR boxes of slanted words can be off by about a line, and Windows OCR does not read
  lines slanted by ~15 degrees or more (`Dossier Test 7`, `known_miss`). Words of slanted lines are read again turned
  straight (`engine._refine_slanted`, lines of the same slant together) and painted in their own frame
  (`render.paint_tilted`, `_ink_band`); the report boxes (PDF points) are checked by `check_all.check_tilt`.
- Faces: frontal detector (profiles may be missed), tested on public-domain portraits (tools/test_faces) and
  generated pages (Dossier Test 6). Signatures are still ink-based: on a card photographed on a dark table or on a
  printed chip they can grow into a large box (over-redaction, never a leak).
- MRZ only exact for fields read on the page (sex often `<` with Windows OCR); MRZ in a digital text layer not handled.
- Photo / QR / MRZ detection are image heuristics tested only on generated documents.
- Text inside images of digital pages is only replaced where OCR reads it; the rest of the image is kept.
- Fake names are chosen by letter count, not rendered width; bold not detected on ID documents; scan font is Arial.
- A partly covered image stays in a digital output with the covered pixels overwritten.
- Ideas: review table with checkboxes instead of raw YAML, click-to-add from the viewer, highlights on the original,
  MRZ in digital text layers, a second leak check that re-runs the detectors on the output.

## 14. Environment notes (Windows)

- Git Bash: forward slashes, `source .venv/Scripts/activate`; use `python -m pip`. Python 3.12 (`py -3.12 -m venv`).
- Inline Python in Bash heredocs is fragile with backslashes / quotes: write patch scripts to the scratchpad instead.
- `spacy download` may fail behind HTTPS inspection: install the model wheel URL with pip (see README).
- Offline install for the production PC: `pip download -r requirements.txt -d wheels` then `--no-index --find-links`.
- The user's own anonymized outputs / configs may exist (ignored) inside `sample_data/*`: do not delete them.
