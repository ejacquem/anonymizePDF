# CLAUDE.md – anonymizePDF

Technical description of the project for maintenance with Claude Code. User-facing documentation: `README.md`.
Repo: `C:\Users\Lucas\Project\anonymizePDF` (Windows 10, Git Bash + PowerShell). The user writes in French or English.

## 1. Goal and constraints

- Anonymize PDFs (a few dozen, grouped in **client folders** of 3–5 PDFs) **fully locally**, through a small web app.
- Documents: mostly French, also Belgian / Dutch. Bank statements, contracts, invoices, identity documents
  (passport, ID card). Some are digital PDFs (text layer), some are scans.
- Personal data is **replaced by plausible fake values** of the same length / format, consistent across files.
  Not meant to produce perfect forgeries. What cannot be faked (photos, signatures, QR codes) is **blacked out and
  removed from the file**.
- One reviewable YAML config per folder (`anon_config.yaml`): generated by a scan, edited by the user, then applied.
- **Production PC has no admin rights**: everything must work with pip packages only (hence Windows OCR via
  `winrt`, fonts found through the registry, no system installs required). Python 3.12 / 3.13.
- Server on `127.0.0.1` only, confined to `--root` (path traversal -> 403). Originals are never modified; output is
  `<name>_anonymized.pdf` next to them.

## 2. Rules to keep

- Never commit real PDFs, `anon_config.yaml`, `anon_report.json`, `*_anonymized.pdf` (`.gitignore` covers them;
  `sample_data/` only contains generated fake documents).
- Never commit or share the secret key (`secret.key`); never put a constant salt / key back in the code.
- Never ask for or open real client documents; use / extend the generated test documents instead.
- Public documents (`sample_data/Dossier Public*/`, bank and insurance samples from the internet) are third-party files:
  never commit them; only their list and checksums (`tools/public_samples.json`) are in git.
- Privacy first: when in doubt, cover more (over-redaction) rather than leak. A black box must remove the data from
  the file, not only hide it.
- Keep the scope small, no build step for the frontend, no new heavy dependency (no OpenCV / scipy / PyTorch:
  image analysis is done with numpy + Pillow). The one exception: onnxruntime (CPU, face detection), offline with its
  model file in the repo.
- Commit after each modification, but wait for the user's approval before pushing; commit messages end with the
  attribution line given in the session.

## 5. Pipeline

0. **Per page** (`page_layout`): a page is `scan` if it has fewer than 3 VISIBLE words (`pii.visible_words`:
   text with render mode 3 or opacity 0 – the OCR layer of a searchable scan – does not count), else `digital`;
   a digital page whose images cover >= 2 % of it also has `pixels` (OCR of what the visible text layer does not
   cover, `_pixel_words`). File mode in the report: digital / scan / mixed, plus `page_modes`.
1. **Scan** (`scan_folder`): per page, `_detect_words` on the text layer (digital), on the OCR (scan pages; the
   invisible layer of a searchable scan is read too) and on the OCR of the images (pixels). `fix_digits` on OCR
   text, `detect_all` (structured detectors + NER, line by line) and `_add_labeled` (identity fields by position). Aggregate by (type, normalized value). Persons: full names first,
   names with an initial last, plus their parts (≥ 4 letters). Generate fakes (`Faker.suggest` / `person`), align
   numbers contained in longer ones (`_align_contained_numbers`), drop commented suggestions that duplicate an active
   value, write `anon_config.yaml` (`render_config`). `faker.reserve()` gets every original value first, so no fake
   is a word of the documents and no two names share a fake (with some keys 'Thomas' became 'Julien', the real first
   name of someone else in the same statement).
2. **Review**: user edits the YAML (Config tab). `parse_config` validates it.
3. **Anonymize** (`run_anonymize`): every entry is a literal `find → replace` term (plus optional regex).
   - Only scan pages → `_scan_pdf` (a brand new PDF of images). Otherwise `_digital`, page by page:
     scan pages are rebuilt with `_scan_page` and replace the original page (delete + new page with the image);
     digital pages: `plan_page` → read fonts first (`page_spans`), redact matched words (graphics kept; a match is
     INVISIBLE only when every word it covers is invisible text: `_mark_invisible`, `is_invisible_word` (the word starts
     where an invisible character of `get_texttrace` starts). An invisible match is removed without a fake on top; a
     drawn match always gets its fake, even when an invisible copy of the same text lies under it. Limit: the redaction
     of an invisible match also takes the drawn text it overlaps, if that text is not itself a match), write the fake with `insert_replacement` (same font / size /
     colour / baseline); then `_pixel_pass` if the page has images (OCR minus visible text, redaction with
     `images=2` and the sampled paper colour, fake written as Helvetica text sized on the ink height, MRZ in an
     image rebuilt in Courier); then black boxes (`render.black_out_digital`). Finally annotations deleted,
     bookmarks / metadata / XML metadata wiped, `scrub`, `garbage=4`.
   - Scan page (`_scan_page`): render 300 dpi, OCR, OCR-tolerant matching. Before painting: MRZ zone, photos (if ID page or
     option), QR codes, signatures (excluding MRZ / photos / codes), ink colour, free space, bold. Paint each match with
     the sampled paper colour, write the fake (`scan_text_layout`), rebuild the MRZ, draw black boxes; the page is
     saved as a new JPEG in a new PDF (nothing of the original file is copied).
   - The output is read once (`verify.read_output`: metadata, text layer, OCR when used); both checks work on that
     reading, and a second pass re-reads it because it changed the file.
   - Leftovers are placed: each one has `hits` (page, box in PDF points, text layer and OCR). The viewer frames them in red
     (`.lbox`, `drawBoxes`), and a click on a leftover in the Recap (`locateLeftover`) shows the next place, zooms and centres.
     A click on a value of the config (the original text in the table or in Manual data) finds every place in the
     selected original (`locateTerm`, `GET /api/find`, `verify.find_hits`: the text layer of every page, plus the OCR of the
     pages that are scans or have pictures, without the words already counted) and frames them in blue (`.tlbox`). The
     count is per file; the `found N times` of the config counts the whole folder. Zoom on the word is an app setting (off).
   - Verify (`verify.verify_output`): searches the output for each original value (metadata, text layer, and OCR with the
     tolerant regex whenever the file is not purely digital, or when "OCR check" is ticked). If a scanned file has
     leftovers, `run_anonymize` runs a second pass on its output (the per-file config `fcfg`: a list in the whole
     config is not a per-page dict; the log says when it is not needed): text only (photos / codes / signatures are off in
     that pass, so a box the user removed is not blacked out again, and the report keeps the first pass's boxes).
   - Second check (`verify.leak_suspects`): the detectors run again on what the output still says (text layer, or its OCR),
     with the fake values taken out of the text first (a fake street and the fake town on one line are not an
     address), found the way OCR reads them back (`verify.remove_fakes`, term_regex in OCR mode: a fake IBAN read
     with a space less or a 0 read O left '5802 Participation' as a postcode and a town). Every value found that is not a replacement is listed in the report (`suspects`) and as a warning
     in the Recap. It catches what the config never knew (verify_output only searches the detected values). Types:
     `LEAK_TYPES`, dates and identity values on ID pages, honorific names. A value close to a replacement (ratio ≥ 0.8
     after OCR digit folding, `_ocr_fold`) is a replacement read back by the OCR, not a leak. Test: `check_all`
     reports the second check of every output (`suspects`).
     The values it finds are also offered as commented suggestions in the folder's `anon_config.yaml`
     (`engine.suspect_suggestions`, `_offer_suspects`, at the end of `run_anonymize`): a fake from the key, the info
     says 'second check: still readable in <file> p.N'. The review step stays: the user ticks them (Config tab,
     reloaded by the app after the run) and anonymizes again. A value already in the config is not offered twice. The
     config file is written before the report (the report stays the newer one: the folder is not 'to do'), and only
     if it is still the text the run started with. Each file entry of the report lists `suggested`; the Recap says so.
   - The report is saved after every file (`_save_report`, through `anon_report.json.tmp`), so a batch or a run that
     stops keeps the analysis of the files it has done; the output of a file is written when that file is done. The
     config of a batch is written when the scan of its folder ends (`scan_folder`).
   - Report `anon_report.json` per file: mode, pages, replaced, seconds, items, leftovers, warnings,
     `blackouts: [{page, kind, box (PDF points)}]`, `mrz: [{page, action, format, lines}]`. Each item (one per
     original value) has `boxes: [{page, box (PDF points)}]` = where the value was: scan, digital and pixel-pass
     replacements all record it (`_union_box`), the Changes button draws them.

## 6. Config format (`anon_config.yaml`)

```yaml
ocr_lang: "fra+eng"
case_sensitive: false
match_case: true                    # UPPER / lower / Title case of the original applied to the fake
style: {mode: replace, digital_fill: none, font_match: true, quality_match: true}
                                    # mode: replace | blackbox ; digital_fill: none | white
                                    # font_match / quality_match: scans and pictures (section 10b); missing = true
blackout: {photos: true, photos_only_on_id_documents: false, signatures: true, qr_codes: true}   # photos = faces
mrz: regenerate                     # regenerate | keep   (old value 'blackout' is read as regenerate)
replacements:
  - {find: "Thomas Marchand", replace: "Alexis Beaumont", type: PERSON}
  # - {find: "30/09/2024", replace: "22/03/2025", type: DATE}   # commented = not replaced
regex: []                           # - {pattern: '...', replace: '...'}
# Manual data (written by the app, kept by every scan; a manual value wins over the automatic one with the same text):
manual_replacements:
  - {find: "Acme Corp", replace: "Zeta Inc"}
manual_blackouts:                   # black boxes drawn in the Anonymized pane: PDF points, page 1 = first page
  - {file: "x.pdf", page: 1, box: [x0, y0, x1, y1]}
  # a moved automatic box: origin = photo | qr code | signature, replaces = the box the detector found
  - {file: "x.pdf", page: 1, box: [x0, y0, x1, y1], origin: photo, replaces: [x0, y0, x1, y1]}
```
`auto_changes:` (written by the app) keeps the automatic values changed by hand: `{find, type, original, was_active, removed}`.
`manual_texts:` (written by the app): texts typed by hand, `{file, page, box, text}` in PDF points.
There is no list of removed automatic boxes in the config: they are only sent with an anonymization run.
Missing keys in older configs get the safe defaults (everything on). `find` matching (`pii.term_regex`): case-
insensitive, flexible whitespace, word boundaries; on scans `ocr=True` also accepts 0/O/D, 1/l/I, 5/S, 8/B, 2/Z,
missing accents and a space inside a number. Overlaps (`pii.resolve`): terms beat regex, then the rank, then the longer
match; a match inside a longer one is left out only while that longer one is kept (a town that loses its place to a
street keeps the code inside it); ties are broken by the replacement, never by the order of the config.
Order must never change a result (`order_tests`): a value written with several spellings keeps the most frequent one
(ties: alphabetical), and a town written with several postcodes is one LOCATION term with all its counts.

## 7. Detection (`pii.py`, `fields.py`)

- Types: IBAN (mod-97), BIC (8 or 11 characters with a European country code at 5-6, `pii.bic_plausible`; after its
  label such as 'BIC/SWIFT', or just after an IBAN: a bare word such as 'MONSIEUR' or 'VIREMENT' is no BIC). A BIC is the
  bank's public identifier, not the client's: it is a suggestion (commented out), off by default (`engine.ACTIVE_TYPES`),
  not in the active types. Account numbers after their label may end with a letter ('000012345Y'),
  EMAIL, PHONE (BE/FR/intl), CREDIT_CARD (Luhn), CARD_NUMBER (masked `6703 **** **** 4471`, any run of stars or X
  `495321XXXXXX7425`, `Carte x4412`), BE_NATIONAL_NUMBER, BE_VAT, VAT_NUMBER (Swiss `CHE-123.456.789`, masks kept, or after a TVA / BTW /
  VAT / MWST label, 8+ digits), BE_STRUCTURED_COMM, SEPA_CREDITOR_ID (checksum, or after a label),
  STREET_ADDRESS also without its number ('Rue de Paris', 'rue de la république': keyword, article, name of up to 3
  words, on one line; 'Rue Victor Hugo': capitalised name) and when the street is named after a date ('avenue du 11
  novembre', 'rue du 8 mai 12', number before or after; `_NAME_WORD` stops a name at the words of a sentence). A street
  on one line is not swallowed by a two-line address whose number is on the next line (`pii.resolve`). Fakes
  (`fake.street`): the kind (rue, avenue) and the article stay, the NAME always changes (`_date_street` for dates,
  the phrase list never gives back the same noun). Test: `street_name_tests`. The articles ('de', 'la', 'du') are
  words of every document: they are not checked against the reserved words, so a fake is always a real street name
  (`_STREET_ARTICLES`, `fake.street`); the random-letter `scramble` is never the fallback of a street name.
  STREET_ADDRESS (a street keyword, a name of up to 3 words in any case, then the number; the address can be written on
  two lines, the number ends it and is never the first digits of a postcode; on one line, a street name does not run
  on to the next line; the address after a label to the end of the line: 'Rue : 04 Library place'; English number
  first: '04 Library place'), POSTAL_CITY (postcode + city in Title case or CAPITALS, prefixes B-, F-, CH-, L-, NL-,
  D-, I-, A-; not 'Code' / 'Banque' / 'Guichet'...), a town followed by its postcode in brackets ('NANTERRE (92000)',
  'BOULOGNE-BILLANCOURT (72000) (FRANCE)': the value is the town and its code, `_v_town_code`; a year in brackets is no
  postcode; the fake keeps the brackets and the town of the term alone, `fake.postal_city`, `engine._town_of`), the town
  at the end of an address is a POSTAL_CITY too,
  ACCOUNT_NUMBER (after "N° de compte" / "Numéro client" / "Compte" / "Compte courant" / "RIB" on the same line, or without
  label when it is five or more digits and one capital letter ('0012345Y', '12345 Y', not running text), with spaces, '-', '.' or '/' as separators, French RIB, long digit runs, apostrophe-grouped digits
  `86'123'456'789'012` with masks, at least 3 groups so amounts `1'240.00` are not caught),
  BANK_CODE ("Code banque / guichet", "Clé RIB"), CONTRACT_REF ("police", "contrat", "dossier", "REF" with letters and
  digits, and an identifier written alone 'BT187536HE8O43': lowest priority), DOC_NUMBER,
  BIRTH_PLACE, DATE (`/ . -` or spaces `14 05 1992`), PERSON, NER ORG / LOCATION (always commented out).
- Page text normalises Unicode dashes (U+2010…) to `-` one-for-one (`words_to_text`), so spans stay valid.
- A word cut across two lines ('JACQUEM' / 'IN LUCAS') is joined in the page text (`pii._cut_words`, used by
  `words_to_text`) only when the joined word (6 letters or more, letters only) is written whole elsewhere on the same page
  ('JACQUEMIN LUCAS'). Without that evidence the lines stay apart. Tests: `split_word_tests`. A real
  PDF used U+2010 inside a national number and hid it from every detector.
- Split types: groups of ≥ 5 digits of ACCOUNT_NUMBER / BANK_CODE and ≥ 4 digits of masked CARD_NUMBER are also
  separate entries (OCR may drop the stars); digit groups get the same fake everywhere (`Faker.digit_groups`).
- Dates are active only for birth dates (`_BIRTH_RX` within 35 chars before / 8 after, or a birth-date label).
- Bank operation labels (`pii.OPERATION_WORDS`: VIRT, RECU, PRLV, SEPA, REF, RET, DAB, FR, ACHAT-DEBIT, ...) are taken
  out of PERSON / ORG / LOCATION candidates (`strip_operations`, in `_detect_words` and the second check): 'VIRT RECU
  MARION' is the name 'MARION', and a label alone is dropped. Add a label to the list when a statement shows one.
- OCR misreadings handled by the detectors: an 'Avenue' whose A is read as two marks ('i\venue', '/\venue':
  `pii._FR_STREET`, `fake.street` writes 'Avenue'), an international phone number going on to the next line ('+32 4' /
  '341 27 90'), the m of a title read 'nl' / 'rn' / 'ni' ('Nlonsieur': `engine._ocr_m` in `is_label_word`).
- PERSON: titles in any case ('MLE', 'Mle', 'Mme'); `Prénom NOM` with up to two middle names and a surname cut to 2+
  letters ('Merve Chantal Gaëlle REYES', 'Chantal Gaëlle RE'); capitals only ('REYES MERVE') are candidates, and a
  capitals run that holds another value ('BIC BNPAFRPP') is no name (`detect_structured`, CAPS_NAME_RANK). Candidates
  sharing a word with an active name are active ('REYES MERVE' after 'MLE MERVE REYS'), and the other spellings of a
  name word in the documents are its variants ('REYS', 'REYE' for 'REYES', `engine.name_aliases`, 85 % alike).
  Runs of capitalised words (`pii.CAP_SEQUENCE`, initials count, up to six words) that hold a known name word (a first
  name of the list or a word of an active name) are names too, without a title or NER ('Théo Morin', 'Lucas Martin Lu',
  'Théo A Morin'). A run stops at a stop word, a town, a bank operation label or a word with a digit. A title keeps up
  to five words ('Monsieur Théo Aurélien Gaspard Morin').
  Common words are no names: months and finance / statement vocabulary are stop words (`_STOP`), and a name found only
  by the NER model is active only when none of its words is an ordinary word of the documents (`vocab`: a word written
  in lower case somewhere, standalone, not in an e-mail). A candidate with a stop word or an ordinary word is not even
  suggested ('Jun Bill payment', 'Capital Invested', 'May Start': Dossier Test 14).
  Active PERSON: after a title, contains a known
  first name, spaCy Title Case, or found under a label. `_STOP` words (including label words such as signature, nom,
  nationalité, adresse) are never names. Titles (M, MME, MR, MLE, MLLE, Monsieur, Madame, Maître...) and notarial /
  bank labels (Page, Compte, Alliance, Succession, Mutation, Novembre...) are in `_STOP`: they split a run of capitals,
  so 'MLE Ambre Lefèvre' keeps 'Ambre Lefèvre'. A single ordinary word is only an uncertain suggestion when it is a
  known first name. Headings, English street words and job titles are stop words too ('Standard', 'Time', 'Form',
  'Description', 'Drive', 'Directeur'): a run with one of them is no name, and a name shared with an active name is
  not activated when it holds one ('Sample Drive', 'SAMPLE FORM'). A label alone above a value on a page that is no
  identity document ('NOM' over a column of a specification) is only a suggestion ('under a label - check it'); a label
  with a colon ('Nom : Dupont') stays active. An honorific is not read after a dot ('a.m. Standard Time'), and a photo
  credit ('Photos : R. Richter') is no name. `_NAME_CONNECTORS` ('and', 'y', 'de'...) only counts in lower case: 'Y.' is
  an initial.
  A label word is also one or two letters away from a stop word (`is_label_word`: 'SUCCËSSION', 'COMPTÈ', 'COMTPES' from
  the OCR), and the words at both ends of a name that are labels, titles, towns, operations or connectors ('DE', 'LA')
  are trimmed (`trim_name_edges`): 'SUCCESSION DE Lucas Martin' keeps 'Lucas Martin'. A run of one digit of 7 or more
  ('111111111111', a barcode read by the OCR) is no number (`pii._repeated_digits`).
- Identity by shape (`fields.identity_shape`, identity documents only, see `is_id_document`): when the labels are not
  read (poor copy), the 9-character document number (letters and digits) and the words that are CAPS or Capitalised and
  not boilerplate (`_ID_BOILERPLATE`, fuzzy: `is_boilerplate`, so 'Sumame' is 'Surname') are PERSON / DOC_NUMBER,
  active without a label. Only used when fewer than 3 labelled fields are read (otherwise the labels are read, and
  the shape finds the label words: 'Date', 'Code', 'Country' replaced as names). Labelled values that are a label
  word ('Sumame' read as the surname) are dropped in `_add_labeled`. Every date of an identity
  document is a birth / identity date (replaced). Also used by the second check.
- A name written on the label's own line ('Nom / Name Jacquemin', `fields.inline_value`) skips the label words, and
  the label words the OCR garbled ('Nom I Sumame': `_label_misread`, 75 % like a long label word). Without that
  'Sumame' was taken for the surname and the real one on the line below ('LEFÈVRE') was never read (Dossier Test 03).
- Identity fields (`fields.find_labeled`): label lines (FR/EN/NL; OCR reads `/` as `I`, `°` as `'`) and the value
  line right below (left-aligned, within ~2 line heights) or after `:`. Kinds: surname, given, birth_date,
  birth_place, doc_number, sex, expiry, issue, country, address (several tight lines). `is_id_document`: MRZ found,
  ≥ 2 identity labels, or a keyword (passeport, carte nationale d'identité, permis de conduire, ...).

## 8. Fake values (`fake.py`, `secret.py`)

- Deterministic for a key: `HMAC-SHA256(key, variant|kind|normalized value)`. The 256-bit key is created once per PC
  (`%APPDATA%\anonymizePDF\secret.key`, `ANON_SECRET_FILE` overrides, `O_EXCL` creation, corrupt file → error, never
  silently replaced). Same key → same fakes in every folder. A constant salt allowed a dictionary attack (fixed).
- Towns (`fake.town`): one fake town per town name, whatever form it is written in ('PARIS', '75017 PARIS', 'PARIS'
  in a sentence: the same town); its postcode belongs to it (`FR_TOWNS` / `BE_TOWNS` hold a real postcode per town).
  A town of the document is a LOCATION term in the config (`scan_folder`), so the same town written alone is replaced
  like the town of a postcode. A capitalised town is never a person ('Sophie PARIS' is no name).
  The fake keeps the length of the original: a long name ('BOULOGNE-BILLANCOURT') gets towns of the list joined by a hyphen
  (`fake._compound`, 'MONTAUBAN-CHAMBERY'), since a short town leaves a gap before what follows on the line (the same width
  in a digital text and in a scan: `town_size_tests`).
- Names: FR/BE/NL lists by length and **gender** (`gender_of`: lists, then the title, then French endings; the
  `Sexe` field wins on ID documents). Keys without case / accents (`_pkey`: `Élodie` = `elodie`, used in e-mails).
  `Faker.names` memory keeps consistency: initials follow the replaced first name (`initial`, preferring first names
  seen with the same surname), names ≥ 80–85 % similar (OCR misreading) reuse the replacement (`_similar_name`).
  A replacement can never be the original without accents (`Inès` ≠ `Ines`).
  Spellings of one name share one replacement (`Faker.aliases`, from `engine.name_aliases`: 'REYES', 'REYE', 'REYS').
  Kinds of the words of a name (`Faker.name_kinds`, `engine.folder_kinds`): a known first name is 'first'; capitals next
  to a capitalised word are the surname ('Océane Zaïra REY'); a word known from another active name keeps its kind.
  Middle names are first names: in a name of three words or more, every word but the last is 'first' (`name_kinds`).
  A cut form of a name word ('Gasp', 'Gas', 'Mo') gets the replacement of the full word, cut the same way ('Gaspard' ->
  'Mickaël', 'Gasp' -> 'Mick'), of the kind the full word got (`engine.name_truncations`, `Faker.truncations`).
  A street name never reuses a word of the documents (`Faker.reserved`). English streets: people-like names.
  The town of an address is replaced like the town of a postcode (`Faker._address_tail`).
- Other types: phone keeps format + first 2 digits; IBAN country / grouping, valid checksum; BIC keeps country;
  e-mail keeps common domains; streets from lists (article + noun replaced together, people-like names for long
  ones), towns matching the postcode's country; dates shift (same fake whatever the separator); BE national number
  uses the fake birth date of the same person + valid check digits; SEPA creditor id valid; doc numbers keep their
  letter / digit pattern; masks (`****`, `x`) kept. A town is not picked through the 'no two values share a fake' rule
  (it depends on the town name only, see Towns). A fake never contains a group of 4+ digits of an original value
  (`Faker.reserved_digits`, filled by `reserve`): a fake card or account number holding '4471' would look like a leak.
- `match_case` (engine) applies UPPER / lower / Title case of the matched text.

## 9. OCR (`ocr.py`)

- `engine()`: Tesseract if found (TESSERACT_CMD, PATH, Program Files, %LOCALAPPDATA%\Programs), else Windows OCR
  (`winrt-Windows.Media.Ocr`, one language: the first of `ocr_lang` installed in Windows). `pip install tesseract`
  is an unrelated package.
- Windows OCR quirks: ~1 s/page, reads some `0` as `O` (handled by `fix_digits` + tolerant matching), drops isolated
  letters (the `F` of Sexe) and sometimes whole labels, reads only part of a passport MRZ line 1 and none of an ID
  card MRZ, even on cropped / enlarged lines.
- Tesseract: two passes (`--psm 3`, then `--psm 6` split at column gaps), best reading kept per line.

## 10. Rendering

- Digital (`insert_replacement`): font = the embedded font if it is a subset that carries every character the document
  writes with it (`FontBook.chars`: a subset may still report glyphs it does not have, which drew 'Î' and 'Y' as gaps),
  else the same font installed on
  the PC (Windows registry HKLM + HKCU, no admin: e.g. Consolas → consola.ttf), else the closest base-14. Same size,
  colour, baseline, inside the original box (the Changes frame): a text wider than the box is squeezed sideways to
  90 % of its width at most (`morph`), then made smaller (height 70 % at least, width 60 % at worst;
  `render.SQUEEZE_FLOOR` / `SIZE_FLOOR` / `SQUEEZE_MIN`). A value on several lines has one box per line. `digital_fill: none` keeps
  the page background (redaction with `fill=False`). A value on several lines gets its replacement cut across the same
  lines (`scanpaint._cut_lines`, digital and scan), each line with its own baseline.
  A value on one horizontal line is redacted and placed at its own glyphs (`render.exact_box`: the union of the glyph
  boxes of the value, narrowed by 0.3 pt so that the neighbours which only touch are not taken), not at the word box
  cut in proportion to the characters (wrong for proportional fonts and spaced text). Whatever a redaction still takes
  beside a value is written again (`render.glyphs` before, `restore_collateral` after, for the digital matches, the
  black boxes and the pixel pass). A digital line that is not horizontal (vertical, skewed: its span `dir` is not (1, 0)) is handled as a whole:
  `render.rotated_extent` reads the exact glyph positions of the value from the characters (a word box of a slanted
  word overlaps its neighbours), `rotated_quad` is the area redacted, `insert_rotated` writes the replacement on the
  baseline, turned with the line (`morph` matrix (dx, -dy, dy, dx): PyMuPDF's y axis points down). PyMuPDF removes the
  text whose box touches a redaction's bounding box, which takes the glyphs next to a turned value: those still missing
  after the redaction are written again (`neighbour_glyphs` before, `redraw_missing` after). Scanned turned text is only
  handled up to the tilt range of the scan path (`regions.TILT`, about 20 degrees): a scanned column written vertically
  is not covered.
- Typed texts (`render.paint_text_box_pdf`, `paint_text_box`): the box is removed (redaction filled with the paper
  colour, then a rectangle of the same colour for the lines), the text is written with its height filled by the box and
  its width stretched to the box (`morph`, or a mask resized on scans). Scans: `stretch_layout` / `write_text`; the
  text takes the font of the words under its box (`PageFonts.face_for`, font_match on) and the page's quality with the
  grain of the box (quality_match on), else Arial, sharp, as before (`render.paint_text_box(face=, q=)`).
- Scans, the value's box: a word only partly covered is cut by the Arial widths of its characters (`pii._advance`,
  `match_boxes`). `render.ink_start` skips a colon-like first mark only (narrow, a few rows of the text height, a gap
  after it), so a colon before the value is not counted; a letter is never skipped (an 'A' keeps its foot and is
  replaced). The paint does not widen to the left of the value. Tests: `colon_tests` (Dossier Test 16: a good and a poor
  scan with colons, `colon_truth.json`, compared by the shape of the ink down each colon) and `first_letter_tests`.
- Scans: text sized from the ink height of the original (tight OCR boxes), same baseline, ink colour sampled, paper
  colour sampled for the patch. Bold (`BoldMeter`): median horizontal ink run / estimated font size vs the page
  median, bold if > 1.4× (calibrated against Test 1's digital twin). Fails on ID documents (mostly bold text, no
  regular reference). Font: Arial / Arial Bold. A replacement wider than the OCR box is squeezed sideways (`render.write_text`, mask resized)
  to 90 % of its width, then written smaller; never over the next field (`scan_text_layout`, same rule as digital).
- Scans, font and quality (section 10b) replace the Arial and the flat patch when `style.font_match` /
  `style.quality_match` are on (default).
- MRZ (`draw_mrz`): OCR-B if installed, else Consolas. The character advance comes from the OCR box of the chevron
  line (`find_mrz`, not from the ink of the page: a card edge next to the MRZ made the text too wide). The old text is
  erased pixel by pixel (`_erase_ink`: dark pixels take the local paper colour), never with a flat rectangle, then the
  new lines are written with the same ink colour, and with the page's quality (blur, spread, grain of the area around
  the zone: `scanpaint.page_quality`, `render.draw_mrz(q=)`) when the quality is matched, so they are not sharper than the
  card. `mrz_typed_quality_tests`.

## 10b. Font and quality of scanned text (`fontmatch.py`, `quality.py`; plan and results: docs/font_matching.md)

- Candidates (`fontmatch.CATALOG`): Windows fonts (font folders, no admin) + `anonymizer/fonts`; a family not found
  is skipped. A Face = family + bold (+ file). The italics are families of their own ('Arial Italic' = ariali.ttf /
  arialbi.ttf), 14 of them where the files exist: a slanted word takes an italic face and its fake is written slanted
  (`italic_tests`). They make 74 faces instead of 46 on a computer with all the Windows fonts.
- Font of a word (`word_scores`): the OCR text rendered in every face (`template`, 64 px, cut to its ink), compared
  with the ink of the word (`ink_crop`) at 24 px high: correlation of the shapes minus 1.6 x |log width ratio|. A face
  far too wide / narrow (0.35) is not compared (`WIDTH_PRUNE`). Once the page quality is known the candidates are
  blurred like the page (`softness`: blur + low resolution), so lost serifs are lost in the candidates too.
- Words are measured without the punctuation OCR glues to them (`clean_word`: 'VERHAEGEN,' -> 'VERHAEGEN', the box
  cut before the comma and not widened on that side: the faint comma tail made words look smaller and regular). A word
  with '\' or '|' (an OCR misreading, 'i\venue') is not measured.
- Font of a value (`PageFonts.face_for`): its words count twice, the other words of its OCR line once (Windows OCR
  often gives label and value different line ids); the family wins over the words, then the weight is decided on the
  value's words only (`bold_score`, bold above 0.5): the mean of two clues, the error of the bold rendering against
  the regular one (degraded like the page; 1 -> 0, 0.4 -> 1) and the ink mass of the word against the regular
  rendering's (a blur keeps the total ink) relative to the page's regular text (30th percentile of its words: a page
  can be half bold). 233/234 words of Dossier Test 17 (228 and 231 with each clue alone). BoldMeter is the fallback.
- Words of one value in two weights ('Lucas' regular, 'JACQUEMIN' bold): when the fake has as many words as OCR read
  in the box (`word_faces`), and the words' bold scores spread by >= 0.3, each word is written in its own weight;
  else all in the pooled weight (4-digit groups of an IBAN alone are weak evidence). `scanpaint.layout_value`,
  `render.scan_runs_layout` (runs of text in different fonts on one line). A line of a value on two lines takes the
  weight of its own words.
- Size and baseline (`PageFonts.metrics`): every word of the value rendered in its face and fitted row by row on the
  scan (`fit_rows`: scale and top that correlate the ink per row), medians over the words; the box of a long value on
  a page turned by 0.8 degree is taller than its letters (fakes were 10-15 % too big). A value whose words cannot be
  measured takes the size of its line's other words.
- Filling (`layout_value`, `scan_runs_layout(fill=)`): when something follows the value on its line (a comma, the next
  word: `PageFonts.followed`), a shorter fake spreads to its box: spaces up to +60 %, letters up to 8 %.
- A value on two lines is cut by the words of the same rank when the fake has as many words (`scanpaint._cut_lines`:
  'i\venue' / 'de la Closière 7' -> 'Avenue' / 'de la Chapelle 2'), else by the widths of the lines.
- Quality (`PageFonts.page_quality`, `quality.fit`): on the 20 longest words of the page (>= 3, else not fitted):
  native resolution from the PDF image (`scanpaint.native_scale`, not fitted), then blur and stroke spread by a
  coordinate search over grids, error = linear fit of the degraded candidate to the pixels. Per value: grain (MAD of
  the paper around the box, ink and its edges left out) and colours (`colours`: ink = paper + (darkest 5 % - paper) /
  peak coverage of the degraded candidate: the ink of a full stroke, consistent with the fitted blur), measured on
  the value's longest word, else its line; the page's ink (median of its 8 longest words) when that is missing or
  30 levels lighter (`INK_LIGHTER`: a few short words or digits measured too light an ink). A stroke spread is kept
  only when it lowers the fit's error by 3 % (`SPREAD_GAIN`: a faded copy faked -0.25 px and thinned every fake).
- Painting (`quality.erase`, `quality.paint`): the box is painted with the paper colour plus grain (noise made at the
  native resolution, seeded by page / value / line: a rerun gives the same file); the text is rendered 4x, spread,
  brought to the native resolution and back, blurred, laid in the ink colour, grain on the strokes.
- Fake text quality (app setting, `run_anonymize(quality_offset=)`, kept in the report): the detected quality is
  corrected by `quality.adjust` before painting. Below 0, per 0.1: +0.2 px blur, +1 grain level, -5 % resolution;
  above 0 the blur, grain and spread shrink in proportion and the resolution comes back; +1 = sharp. 0 = as detected.
  Test: `quality_offset_tests`.
- Slanted words (|angle| >= TILT_MIN) are not measured on the page (their OCR box is not their ink, `page_fonts(skip=)`):
  a slanted value takes the page quality, and its font is measured in the patch `paint_tilted` turns straight
  (`render.tilted_face`: the value's text and its ink box in that patch, a PageFonts of one word), Arial when it cannot
  be measured or when the font matching is off (`tilted_font_tests`).
- Ink tails (`render.ink_tail`, `erase_tail`): the OCR box can cut a descender or an ascender (the tail of a Garamond
  'J' goes far below its baseline) and a dot was left under the replacement. The ink connected to the ink inside the
  value's padded box is found by growing it (numpy, at most 0.8 text heights), never into the other words (the parts of
  the value's own word on both sides of it count as other words: `scanpaint._beside`) or the black boxes, never through a
  ruled line (runs of ink longer than 3 text heights are not letters), and dropped when it holds more than a third
  of the box in ink. Erased with the paper colour (and its grain). `ink_tail_tests`.
- A word only partly covered by a value is cut by the widths of its measured font (`PageFonts.advance` ->
  `pii.match_boxes(advance=)`), not Arial's (a monospaced e-mail cut like Arial left pieces of letters).
- Pictures of digital pages (`_pixel_pass`): the same looks; every value is erased on a copy of the page image, the
  fakes are written there, and each value's area (box + its text, a descender may go below the box) is inserted as a
  new PNG over the redaction. Options off: Helvetica text as before.
- Trace items of replaced values have `look` ('Calibri Bold, 200 dpi, blur 1.0px, spread +0.00px, grain 4'), shown in
  the Trace tooltip; the page log lists the fonts used and the scan quality.
- Fake names by width (`Faker._pick_name`, `engine._name_faces`): the fakes were picked by letter count, so a wider
  one was squeezed and a narrower one left a gap. `scan_folder` keeps each scanned page (grey image, words), and once the
  names are known it measures a rough face (`PageFonts.quick_face`: best summed score of the value's words and three of
  its line against sharp candidates, no page quality) of up to `NAME_FACES_PER_WORD` (3) occurrences of each name word
  (through the aliases). `Faker.faces[key]` then lets `name_token` choose, among the valid candidates (same rules,
  length within 3 letters), the one whose width in those fonts (`face.font(64).getlength`, styled like the original) is
  closest to the original's; candidates within 1.5 % of the best (ln) are equals and the key decides, so the same key
  gives the same fake and the name memory keeps the files consistent. Without faces (digital documents, no scan) the
  letter-count pick is untouched. `stats['width_error']` and the log say the gain: mean |ln width ratio| 11.0 % ->
  2.4 % on the 23 name words of Dossier Test 17 (`name_width_tests`). Cost: the scan of Dossier Test 17 takes
  ~9 s more (names in 16 fonts on 3 pages).
- Limits: close look-alikes are mixed up on soft copies (Arial / Roboto, Courier New / Courier Prime, DejaVu Sans
  Bold / Verdana Bold); a page entirely in bold is read as regular with ink spread; ~0.1-0.3 s per value.

## 11. Identity documents: MRZ, photos, QR codes, signatures

- **MRZ** is never read back and never blacked out: always rebuilt in the same format (`mrz: keep` to leave it).
  `find_mrz`: a line with ≥ 4 chevrons from OCR, else `_mrz_by_image` (2–3 unread bands, same height, start within 3
  characters, same pitch, ≥ 19 evenly spaced characters). The ink level is per page (`ink_threshold`: halfway between
  paper and darkest ink, 130–170: a faded copy has grey ink; the fixed 140 lost characters). Other lines above / below
  must look like MRZ too (`_mrz_like`, ≥ 14 evenly spaced characters). Format: 3 lines →
  TD1 (3×30); `P` or > 40 chars → TD3 (2×44); `IDFRA` → FR_ID (old French card 2×36); else TD2 (2×36).
  `_new_mrz`: page fields after replacement (`_fake_text`), doc code / country from the OCR'd first line, names fall
  back on the config's PERSON replacements, missing values random of the right shape; check digits always valid.
- **Faces** (`faces.py`, replaces the old photo heuristic, which was calibrated in mm on flatbed scans and failed on
  photos of cards on a table): YuNet face detector (ONNX Runtime, CPU, offline; the model file is in
  `anonymizer/models/`, its sha256 is checked before loading). Runs on the whole image at 640 px, at 1280 px and at
  full size (windows of 640 px, 75 % overlap) and on the three quarter turns for the coarse scales, merged by NMS
  (score ≥ 0.6). The box is widened to the whole head (+20 % sides, +35 % hair above, +15 % chin). Digital pages are
  rendered at 150 dpi and searched the same way. Kind in the report: `photo`. Searched on every page unless
  `photos_only_on_id_documents: true`. Limits: frontal model (profiles can be missed), no face on a document
  that is far below ~25 px.
- **QR / 2D codes** (`find_codes`, 100 dpi): dark modules merged by closings (`morph.close`, 3 / 5 / 7 px) into a mostly solid square
  7–60 mm; accepted if fine checkerboard (density 0.3–0.75, ≥ 0.45 transitions / mm both ways) or structured
  (`_code_structure`: QR finder squares in ≥ 2 corners, or Data Matrix solid left + bottom edges). Digital pages are
  rendered at 150 dpi and searched the same way (image and vector codes).
- **Signatures**: `is_signature_label` (signature / handtekening / unterschrift among the first two words of the line,
  or a line of ≤ 4 words — not a sentence; `firma` was dropped: it means "company" in NL/DE). Also the closing formulas,
  approvals and places of a signature written without its word (`_SIGNATURE_ANCHOR`: 'Cordialement,', 'Lu et approuvé',
  'Pour l'entreprise', 'Fait à Paris, le …', 'Le titulaire', 'Signé à …'; a line of ≤ 8 words). A line is cut into labels
  where the gap between two words is over 2.5 word heights (`_label_segments`: two columns on one row are two labels).
  Each stroke belongs to ONE label (`_owners`): the nearest label above it in its column (within 8 label heights), else
  the label below it (within 2 heights). So two signatures stacked between labels are two boxes, not one across the
  label. The search goes 30 mm below a label and stops at the next signature label of the column. Ink not OCR text of
  normal height, not a ruled line, not in MRZ / photos (the face area widened by 50 %) / codes; seeded next to the
  label, grown through strokes ≤ 3 mm apart (`_grow`) in a window of 12 mm above / 30 mm below the label and 5 / 80 mm
  around it. A signature with no label (only a typed name under it) is not found: a known limit. Components that are solid (fill ≥ 0.4) or lie mostly inside an OCR word box are print, not ink.
  The label is spared only if the strokes do not touch it. Digital: drawings / images grown the same way.
  A box never covers an OCR word: it is cut on the side that keeps the most dark (signature) pixels and still holds
  the middle of the label (`_clear_of_text`, `ink_mass`). Known limit: a signature on a card whose guilloche is
  connected to it gives a wide box (Reel "Lucas Jacquemin Id Cards": 62 x 12 mm, lower part of the card).
- **Slanted text** (`regions.text_angle`, `line_angles`): skew by projection profile (-20..20 degrees, fine step).
  Lines of ≥ 1.5 degrees are painted turned: the patch is turned straight, erased and written there, turned back, and
  only the changed pixels are pasted back. A line with an unreliable measure takes the common slant of the page.
- **Removal guarantee** (verified by extracting the output objects): scans are rebuilt from one new image per page.
  Digital: `black_out_digital` redacts with `images=2, graphics=2` (text removed, covered pixels overwritten, fully
  covered images and their SMask dropped, touched drawings removed — MuPDF's "remove if covered" mode keeps
  strokes, i.e. signatures), redraws the collateral lines that are not inside a box (frames, table borders) from
  `get_drawings()`, then paints the boxes again on top.

## 11b. Speed (what is shared, what is cached, and what must stay exact)

- A scanned page is measured once in `_scan_page`: one grey copy of the page (`gray`), one skew memo shared by the two
  `line_angles` passes (a crop measured once is not measured again, `regions.line_angles(memo=)`).
- Square max / min filters (`morph`) replace PIL's rank filters: identical results, 10 to 30 times faster. Used by the
  code search and the paper colour of the MRZ erase. PIL can crash (divide by zero) on a kernel larger than a small
  image: do not use it as the reference there.
- A digital page is rendered once at `ocr.DIGITAL_DPI` for the face and code searches (`_digital`).
- The ink level of a page (`fields.ink_threshold`) is computed once per MRZ search, and passed on.
- OCR cache (`ocr.ocr_words`): the reading of an image is remembered, keyed by the pixels (sha1 of the array, ~20 ms for
  a page), the engine and the language. The scan and the anonymization render the same page the same way, so the
  second OCR of a page is a lookup. In memory only, bounded by the number of words (`ocr.CACHE_WORDS`, least recently
  used out); the words are copied in and out. Never on disk next to the documents. The one disk use is the test suite's:
  `ANON_OCR_CACHE_DIR` (a folder of the run's temporary directory) shares the readings between its processes.
- Profile of a scanned page (`cProfile` on `run_anonymize` of the insurance contract, Dossier Test 17, 3 pages, 33 s):
  the time was in the font and quality measures (`fontmatch.PageFonts`), not in the OCR (3 s of 54 s for the folder).
  Done, results identical: `fit_rows` takes all the tops of a scale at once (np.corrcoef called 69 000 times was 8 s of
  33; the argmax is the first of the equal ones, as the loop), `bold_score` is remembered per (words, family) (the layout
  steps asked it again and again), `quality.blur` adds the taps in place for a big array (same additions in the same
  order, bit for bit the same), `word_scores` compares the faces of a word as a stack (`compare_many`, `blur_stack`:
  also bit for bit). 33 s -> 23.5 s. A value that ends under a black box or in the MRZ gets no look measured
  (`page_looks(covered=)`, scan pages and pictures). Left: the face detector windows (~1.6 s a page at 300 dpi, the
  model's cost), the probe renderings (`_rendered`, PIL text drawing of every word in ~46 faces), page quality fit.
- Every speed-up keeps the results identical. Check it with `tools/snapshot_results.py`: `save` before and after a
  change (`--code <root>` runs an exported older commit), then `compare` prints IDENTICAL (configs, reports, output
  hashes without PyMuPDF's random document ID, page pixels, text layers) and the time of both runs. The random ID is
  written as two hex strings or, when its bytes allow it, as literal strings: both forms are stripped (`ID_RX`; with the
  hex form only, a file or two of 39 differed from its twin in some runs, which looked like a regression). Run the two
  snapshots one after the other on an idle machine: the timings are meant to be compared.

## 12. Test suite: `python tools/check_all.py`

Run it after every change (exit code 0 = all passed; about 8 min with 2 keys on 4 cores / 8 threads (1417 checks), it was 17 min
one job after the other; `--quick` = 1 key and no option tests, `--fast` = also leaves out the long font / contract runs
(`SLOW_GROUPS`), `--folder "Dossier Test 04"` to target, `--keep` to keep outputs, `--jobs N` processes at once, default 6,
1 = one after the other with live output). It copies `sample_data/*` to a temp dir and uses
temporary random keys (`ANON_SECRET_FILE`), never the user's key, never writing into `sample_data/`.
The run is a list of jobs (`build_jobs`, `run_job`): each group of tests, each test folder with each key, and the option
tests. A job runs in a spawned process with its own temporary directory and key; what it prints is kept and shown in the
order of a sequential run, so the output does not depend on `--jobs`. The longest jobs start first (`WEIGHT`, seconds
of a sequential run) and the summary names the five longest. The test groups use one fixed key (a hash of a label, not a
secret): their thresholds are measures on pixels (the weight of short words in `contract_tests` fails by one word with
some random keys); the folder runs and the option tests use the random ones. Workers get one thread each (OMP / OpenBLAS
/ MKL and `ANON_ORT_THREADS`, read by `faces._load`). The jobs share the readings of the OCR through a folder of the
run's temporary directory (`ANON_OCR_CACHE_DIR`, see section 11b); the gain is small (OCR is ~1.5 s of a 50 s folder
run), the time is in painting the fakes.
A run with a failure keeps its key (copied to the temp folder, `anonymizePDF_check_keys`, outside the repo) and the summary
prints it with the replay command: `python tools/check_all.py --key <file> [--folder ...]` (the file is only read; the
user's key and the kept keys are never committed). `tools/key_hunt.py` runs one digital test file with many random keys
(parallel processes, the folder's scan and the names model as check_all) and keeps the keys that leave a sensitive
value in the text layer: `--folder "Dossier Test 01" --file releve_banque_mosane.pdf --keys 150 --jobs 5`.
- Per output file: no error; expected mode (digital / scan / mixed); **leaks** in the text layer, a fresh OCR of every
  page and the metadata (names as whole words, numbers / multi-word values as substrings, accent-insensitive);
  report leftovers empty; expected black-box kinds, each black in the rendering; nothing under a box in digital
  outputs (no text, no drawing but the box, no original image); no original image at all in scan outputs; MRZ
  format, lengths, check digits, fake surname inside.
- Expectations per file are in `EXPECT` (sensitive values written by the generators, mode, box kinds, MRZ formats).
  A new test document needs an entry there.
- Names of several words (`names_tests`): the title keeps five words, middle names are first names, cut forms follow
  the full word, and a run of names with a known word is found without the title rule and without NER.
- Titles and labels (`common_words_tests`, Dossier Test 15 from `tools/make_test_notary.py`): no title or label is an
  active name, and the real names next to them are found. Dossier Test 14 and 15 keep their headings readable (KEEP).
- Reported cases (`reported_cases_tests`): masked cards with X, REF / BT identifiers, 'numero du compte', 'Rue :',
  'MLE', names in another order and cut, 'bis', BIC in capitals, '30002 Code banque', two-line addresses, name
  kinds and spellings, the two-line cut. Dossier Test 02 and 11 are in EXPECT (digital and scan), KEEP holds the
  operation labels of Test 2 ('VIRT RECU', 'PRLV SEPA', 'ACHAT-DEBIT').
- Towns and postcodes (`town_tests`): one fake town per name, the postcode belongs to the fake town, a Swiss postcode
  keeps its length. Detector tests: a BIC of any country after its label, an account with a slash, an address on two
  lines, a postcode that is not the street number.
- Secret key and fake values: key creation / reuse / corrupt file, determinism, gender, initials, e-mails, OCR
  misreadings, never the original without accents, a wrong key does not single out the true name.
- Options: qr_codes / signatures off, `mrz: keep`, old `mrz: blackout`, photos searched on every page of statements,
  a removed photo stays removed on the second pass of a scan.
- Speed-up helpers (`speedup_tests`): morph equals a window reference (edges included) and PIL, the shared skew memo
  gives the same angles, the output is read once and verify finds what is still there.
- Detectors (`detector_tests`, no OCR): the strings the real files showed ('MONSIEUR' is no BIC, capitalised cities,
  Swiss VAT, apostrophe references and amounts, 'Code SWIFT' not a name, identity by shape).
- `KEEP`: values that must stay readable in a digital output (no over-redaction), e.g. 'MONSIEUR'.
- Scan rendering (`name_width_tests`, `tilted_font_tests`, `mrz_typed_quality_tests`, `ink_tail_tests`, `italic_tests`):
  see section 10b.
- Text of scans in sentences (`scan_text_tests`, no OCR: punctuation, line cuts, filling, 'i\venue', a phone over a
  line break, 'Nlonsieur'; `contract_tests`, the insurance contract: no leftover / suspect, every word of every value
  in the weight of the word it replaced, letters of the line's size on the turned pages, ink as dark).
- Fonts and quality (`font_unit_tests`, no OCR: synthetic pages written with a known face and quality are measured
  back, grain, seeded noise, config switches; `font_scan_tests`, Dossier Test 17: font / weight / blur of the
  original lines, the font each replacement was written in, the output measured again (font kind, blur of the
  replacements vs the values they replaced, ink level, grain of the erased area), the pasted picture, a rerun gives
  the same file, options off = Arial on a flat patch).
- Every output has an empty second check (`suspects`): on the original files of the poor copy the same check lists
  the values it sees (a useful sanity check when the test documents change).
- Several keys matter: some bugs only appear with some keys (`Inès` → `Ines`, `Thomas` → `Julien`).
  Case solved with key_hunt (1 key in 150): the '4471' of Dossier Test 01 was a false alarm of the leak search, which
  joined the lines of the text: the fake 'BE96ZZZ0969601447' above '17.947.729' made a '4471'. A value of one token
  is now searched line by line (`found_in`); a value of several words still across lines.
- UI changes: check in the Browser pane (it may be hidden: rAF and scroll events then do not fire).

## 13. Known limits / ideas

- Scans depend on OCR quality; names are heuristic (review step). Leftover check only knows the config's values; the
  second check (`leak_suspects`) is the net for the rest, and it does not replace: it reports (warning) and offers
  the values as commented suggestions in the config.
- Poor copies: a very faint colon can touch the first letter of the value; then a faint fragment of the letter may stay
  beside the replacement (privacy first: the letter is covered, the colon is not guaranteed).
- Poor ID copies: the signature (its label is not read) and a ghost portrait are missed (Dossier Test 09). Masked
  postcodes as they appear after manual masking ('7***7 Paris') are not read; the digits must be on the page.
- Identity by shape can over-redact: a Capitalised word on an identity document is replaced as a name (even a town
  of birth or an OCR fragment such as 'CARO'). Privacy first, and the review step shows it.
- Slanted text (scans, photos): OCR boxes of slanted words can be off by about a line, and Windows OCR does not read
  lines slanted by ~15 degrees or more (`Dossier Test 07`, `known_miss`). Words of slanted lines are read again turned
  straight (`scanpaint._refine_slanted`, lines of the same slant together) and painted in their own frame
  (`render.paint_tilted`, `_ink_band`); the report boxes (PDF points) are checked by `check_all.check_tilt`.
- Faces: frontal detector (profiles may be missed), tested on public-domain portraits (tools/test_faces) and
  generated pages (Dossier Test 06). Signatures are still ink-based: on a card photographed on a dark table or on a
  printed chip they can grow into a large box (over-redaction, never a leak).
- MRZ only exact for fields read on the page (sex often `<` with Windows OCR); MRZ in a digital text layer not handled.
- Photo / QR / MRZ detection are image heuristics tested only on generated documents.
- Text inside images of digital pages is only replaced where OCR reads it; the rest of the image is kept.
- Fake names are chosen by letter count, not rendered width; bold not detected on ID documents; scan font is Arial.
- A partly covered image stays in a digital output with the covered pixels overwritten.
- Ideas: review table with checkboxes instead of raw YAML, click-to-add from the viewer, highlights on the original,
  MRZ in digital text layers, a second leak check that re-runs the detectors on the output.

## 14. Environment notes (Windows)

- Git Bash: forward slashes, `source .venv/Scripts/activate`; use `python -m pip`. Python 3.12 (`py -3.12 -m venv`).
- Inline Python in Bash heredocs is fragile with backslashes / quotes: write patch scripts to the scratchpad instead.
