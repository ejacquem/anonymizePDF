# anonymizePDF: project context

Use this file as context for future prompts or as `CLAUDE.md` for Claude Code.
Repo: `C:\Users\Lucas\Project\anonymizePDF` (Windows 10, Git Bash).

## 1. Goal

Anonymize about 50 PDFs, **fully local**, with a small web app.
- Documents are mostly French (also Dutch/Belgian possible); some are digital PDFs (real text layer), some are scans.
- Not meant to produce perfect fake documents: personal data is replaced by plausible fake values of similar length and format.
- PDFs are grouped in **client folders** (3 to 5 PDFs per client). One config per folder, applied to every PDF in it.

## 2. Decisions made

- Python backend (Flask), vanilla HTML/JS frontend (no build step), PyMuPDF for PDFs, Tesseract for OCR, spaCy for name detection (optional).
- Originals are never modified. Output goes next to them as `<name>_anonymized.pdf`.
- The config is a reviewable YAML file per folder (`anon_config.yaml`), generated by a scan, edited by the user, then applied.
- Dates are **not replaced by default**; only dates near "né le / naissance / geboren / birth" are active.
- Uncertain detections (single names, ORG, LOCATION, non-birth dates) are generated **commented out** in the config.
- Server listens on 127.0.0.1 only and is confined to `--root` (path traversal returns 403).
- Digital vs scan is decided **per file**, not per page (mixed documents get a warning).
- PDF viewer = our own: the server renders pages to PNG with PyMuPDF (`/api/page`), the page shows them in a scrollable column.
  No iframe (its zoom/scroll can't be read or synced) and no PDF.js (no new dependency).

The original numbered CLI scripts (`1_detect.py` ... `4_anonymize_scan.py`) were removed; their helpers live in `render.py`.

Run: `python app.py --root <folder containing client folders>` then open http://127.0.0.1:5000.
Options: `--port`, `--ocr-lang fra+eng`, `--spacy-model` (repeatable).

## 4. UI (left to right)

Directory tree | Original PDF | Anonymized PDF | right panel with tabs **Config / Recap / Log**.
The 3 bars between panes are draggable (double-click resets); widths are saved in localStorage.
Viewer: zoom shared by both PDFs (−/+, Fit = fit width, Ctrl+wheel), scroll synced page by page ("Sync" checkbox).
Toolbar: **1 · Scan & draft config**, **Save config** (Ctrl+S), **2 · Anonymize folder**, checkbox "OCR check for digital PDFs".
Clicking a folder (or a file in it) selects the **working folder**. Tree badges: `N pdf`, `cfg`, `done`.

## 5. Pipeline

1. **Scan** (`scan_folder`): for every non-anonymized PDF directly in the folder, get words per page (text layer, or OCR if fewer than 3 words), build page text, run `detect_all` (structured detectors + NER). Aggregate by (type, normalized value). Generate fake suggestions, render `anon_config.yaml`.
2. **Review**: user edits the YAML in the Config tab.
3. **Anonymize** (`run_anonymize`): applies config (all entries are literal `find → replace` terms, plus optional regex) to every PDF.
   - Digital: PyMuPDF redaction (text truly removed), replacement text inserted, annotations deleted, metadata wiped, `scrub`, `garbage=4`.
   - Scan: render 300 dpi, OCR, paint over matches (background colour sampled), draw replacement, rebuild image-only PDF.
   - Then verify: searches the output for any original value (metadata, text layer; plus OCR for scans or when the checkbox is on).
   - Writes `anon_report.json` (per file: mode, pages, replaced count, seconds, items by type/original/replacement/count/pages, leftovers, warnings).
4. **Recap tab** renders that report; **Log tab** shows the job log (jobs run in a thread, one at a time, UI polls `/api/job/<id>`).

## 6. API (Flask)

`GET /api/info`, `GET /api/tree`, `GET /api/pdf?path=`, `GET /api/pdfinfo?path=` (page sizes), `GET /api/page?path=&page=&scale=` (PNG), `GET|PUT /api/config?folder=`, `GET /api/report?folder=`,
`POST /api/scan`, `POST /api/anonymize` (return a job id), `GET /api/job/<id>?since=N`.

## 7. Config format (`anon_config.yaml`, one per folder)

```yaml
ocr_lang: "fra+eng"
case_sensitive: false
match_case: true          # replacement takes UPPER/lower case of the matched text
style: {mode: replace}    # or blackbox
replacements:
  - {find: "Thomas Marchand", replace: "Alexis Beaumont", type: PERSON}
  # - {find: "30/09/2024", replace: "22/03/2025", type: DATE}   # commented = not replaced
regex: []                 # optional: - {pattern: '...', replace: '...'}
```
`find` is matched case-insensitively, with flexible whitespace and word boundaries; longer matches win; terms win over regex.

## 8. Detection

Types: IBAN (mod-97 checked), BIC, EMAIL, PHONE (BE/FR/intl), CREDIT_CARD (Luhn), BE national number, BE VAT, BE structured communication,
STREET_ADDRESS (FR/NL/BE heuristics), POSTAL_CITY, ACCOUNT_NUMBER (long digit runs), DATE, PERSON, plus NER ORG/LOCATION.
PERSON heuristics (in `anonymizer/pii.py` DETECTORS): after a title (M., Mme, Dr, Mr…), `Prénom NOM`, `NOM Prénom`, plus spaCy PERSON.
`PERSON` is active by default only if: after a title, or contains a known first name, or spaCy found it in Title Case. Otherwise commented out.
Individual name parts (≥4 letters) of accepted names are added as separate entries (so a lone `Marchand` is replaced too).
NER runs line by line (page text split on newlines).

## 9. Fake values (`anonymizer/fake.py`)

Deterministic (hash of salt+type+value), unique per run, same length where possible: names from FR/BE name lists by length (case style kept),
phones keep format and first 2 digits, IBAN keeps country/grouping with valid checksum, BIC keeps country, emails keep common domains,
streets/cities from lists by length, dates shift day/month/year, card numbers keep Luhn validity, other ids change every digit.

## 10. OCR details

`ocr_words()` does two Tesseract passes (default layout, then `--psm 6`). Second-pass lines are split at wide gaps (columns),
and replace first-pass words when pass 1 looks garbled (mean conf < 80 and pass 2 better by 10); if the passes disagree textually, both readings are kept.
This fixed text inside bordered boxes that psm 3 garbled.

## 11. Testing done (in a Linux sandbox)

- Backend end to end on `Client_Marchand` (3 files incl. a scan): 104 replacements, no leftovers, fake values identical across digital and scan.
- Frontend logic with jsdom against the live server (tree, selection, config save/validation, scan, anonymize, recap, log).
- **Not tested**: real browser rendering, the browser PDF viewer inside the panes, Windows runtime (except the user's install).

## 12. Known limits / ideas

- Scans depend on OCR quality (handwriting, stamps, signatures missed). Names are heuristic (hence the review step).
- The leftover check only searches for values present in the config.
- Mixed digital/scan PDFs are processed as one mode per file.
- Replacement text uses a standard font; gender of names is ignored.
- Ideas: review table with checkboxes instead of raw YAML, click-to-add selected text from the viewer, highlights on the original,
  hybrid per-page mode, global mapping file across folders, batch status view, nl_core_news_md for Dutch.

## 13. Environment notes (Windows / Git Bash)

- In Git Bash use forward slashes: `source .venv/Scripts/activate`, `cd /c/Users/Lucas/Project/anonymizePDF`.
- Use `python -m pip …` if `pip` is not found.
- **Use Python 3.12 or 3.13** (`py -3.12 -m venv .venv`). Python 3.15 has no prebuilt wheels for spaCy/PyYAML and tries to compile.
- Install: `python -m pip install -r requirements.txt` then `python -m spacy download fr_core_news_md`.
- Tesseract (scans only): Windows installer with `fra`/`nld`/`eng`; auto-detected in `C:\Program Files\Tesseract-OCR` or `%LOCALAPPDATA%\Programs\Tesseract-OCR`, else set `TESSERACT_CMD`;
  `pip install tesseract` / `pytesseract` do NOT install the program (`winget install UB-Mannheim.TesseractOCR` does); set `TESSDATA_PREFIX` if languages are missing.
- `static/` must contain `index.html`, `app.js`, `style.css` (a 404 on `/` means they are not there; `app.py` now warns about it).

## 14. Rules to keep

- Never commit real PDFs, `anon_config.yaml`, `anon_report.json` or `*_anonymized.pdf` (`.gitignore` covers them; `sample_data/` is fake).
- Don't send real documents to an AI assistant; the fake sample files are enough for development.
- Keep the scope small and the app local-only (127.0.0.1).
