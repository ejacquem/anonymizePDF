# anonymizePDF: project context

Use this file as context for future prompts or as `CLAUDE.md` for Claude Code.
Repo: `C:\Users\Lucas\Project\anonymizePDF` (Windows 10, Git Bash).

## 1. Goal

Anonymize about 50 PDFs, **fully local**, with a small web app.
- Documents are mostly French (also Dutch/Belgian possible); some are digital PDFs (real text layer), some are scans.
- Not meant to produce perfect fake documents: personal data is replaced by plausible fake values of similar length and format.
- PDFs are grouped in **client folders** (3 to 5 PDFs per client). One config per folder, applied to every PDF in it.

## 2. Decisions made

- Python backend (Flask), vanilla HTML/JS frontend (no build step), PyMuPDF for PDFs, OCR = Tesseract if installed else Windows built-in OCR (pip-only, no admin: the prod PC has no admin rights), spaCy for name detection (optional).
- Originals are never modified. Output goes next to them as `<name>_anonymized.pdf`.
- The config is a reviewable YAML file per folder (`anon_config.yaml`), generated by a scan, edited by the user, then applied.
- Dates are **not replaced by default**; only dates near "né le / naissance / geboren / birth" are active.
- Uncertain detections (single names, ORG, LOCATION, non-birth dates) are generated **commented out** in the config.
- Server listens on 127.0.0.1 only and is confined to `--root` (path traversal returns 403).
- Digital vs scan is decided **per file**, not per page (mixed documents get a warning).
- PDF viewer = our own: the server renders pages to PNG with PyMuPDF (`/api/page`), the page shows them in a scrollable column.
  No iframe (its zoom/scroll can't be read or synced) and no PDF.js (no new dependency).

## 4. UI (left to right)

Directory tree | Original PDF | Anonymized PDF | right panel with tabs **Config / Recap / Log**.
The 3 bars between panes are draggable (double-click resets); widths are saved in localStorage.
Viewer: zoom shared by both PDFs (−/+, Fit = fit width, Ctrl+wheel), scroll synced page by page ("Sync" checkbox).
Sync unticked = the browser's own PDF viewer in an iframe (`/api/pdf`, selectable text); the choice is kept in localStorage.
Toolbar: **1 · Scan & draft config**, **Save config** (Ctrl+S), **2 · Anonymize folder**, checkbox "OCR check for digital PDFs".
Clicking a folder (or a file in it) selects the **working folder**. Tree badges: `N pdf`, `cfg`, `done`.

## 5. Pipeline

1. **Scan** (`scan_folder`): for every non-anonymized PDF directly in the folder, get words per page (text layer, or OCR if fewer than 3 words), build page text, run `detect_all` (structured detectors + NER). Aggregate by (type, normalized value). Generate fake suggestions, render `anon_config.yaml`.
2. **Review**: user edits the YAML in the Config tab.
3. **Anonymize** (`run_anonymize`): applies config (all entries are literal `find → replace` terms, plus optional regex) to every PDF.
   - Digital: PyMuPDF redaction (text truly removed), replacement text inserted, annotations deleted, metadata wiped, `scrub`, `garbage=4`.
   - Scan: render 300 dpi, OCR, paint over matches (background colour sampled), draw replacement, rebuild image-only PDF.
   - Then verify: searches the output for any original value (metadata, text layer; plus OCR for scans or when the checkbox is on).
   - Writes `anon_report.json` (per file: mode, pages, replaced count, seconds, items by type/original/replacement/count/pages, leftovers, warnings).
4. **Recap tab** renders that report; **Log tab** shows the job log (jobs run in a thread, one at a time, UI polls `/api/job/<id>`).

## 6. API (Flask)

`GET /api/info`, `GET /api/tree`, `GET /api/pdf?path=`, `GET /api/pdfinfo?path=` (page sizes), `GET /api/page?path=&page=&scale=` (PNG), `GET|PUT /api/config?folder=`, `GET /api/report?folder=`,
`POST /api/scan`, `POST /api/anonymize` (return a job id), `GET /api/job/<id>?since=N`.

## 7. Config format (`anon_config.yaml`, one per folder)

```yaml
ocr_lang: "fra+eng"
case_sensitive: false
match_case: true          # replacement takes UPPER/lower case of the matched text
style: {mode: replace, digital_fill: none}   # mode: or blackbox | digital_fill: none (page background) or white
replacements:
  - {find: "Thomas Marchand", replace: "Alexis Beaumont", type: PERSON}
  # - {find: "30/09/2024", replace: "22/03/2025", type: DATE}   # commented = not replaced
regex: []                 # optional: - {pattern: '...', replace: '...'}
blackout: {photos: true, photos_only_on_id_documents: true, signatures: true, qr_codes: true}  # default on
mrz: regenerate           # regenerate (same format, never blacked out) | keep; old value 'blackout' = regenerate
```
`find` is matched case-insensitively, with flexible whitespace and word boundaries; longer matches win; terms win over regex.

## 8b. Identity documents (passport / ID card)

- `fields.find_labeled(words)`: label lines (FR/EN/NL, '/' may be OCR'd as 'I') and the value line right below
  (or after ':'). Kinds: surname, given, birth_date, birth_place, doc_number, sex, expiry, country. At scan time
  they become active entries (PERSON with forced kind first/last, DATE birth, BIRTH_PLACE, DOC_NUMBER); the
  `Sexe` value sets the gender of those names. Dates '14 05 1992' (spaces) are a DATE format too.
- MRZ (scans): never read back (Windows OCR reads part of passport line 1 and none of an ID card's 3 lines), always
  rebuilt in the SAME format, never blacked out. `find_mrz`: one line found by OCR chevrons, or (OCR read nothing)
  `_mrz_by_image`: 2-3 bands of the same height / start / pitch with >= 19 evenly spaced characters that no OCR
  word covers; extra lines above / below must also look like MRZ (`_mrz_like`). Format from lines + characters
  (ink column runs): 3 lines = TD1 (3x30), 'P' or > 40 chars = TD3 (2x44), 'IDFRA' = FR_ID (old French card 2x36),
  else TD2 (2x36). `_new_mrz`: labeled fields after replacement (`_fake_text`), doc code / country from the OCR'd
  first line, names fall back on the config's PERSON replacements, missing values random of the right shape
  (`build_mrz`, check digits valid). Drawn in OCR-B if installed, else Consolas. Sex not readable -> '<'.
  Report: `mrz: [{page, action, format, lines}]`.
- Photos (scans): darker than the local paper (max filter ~15 mm at 50 dpi, diff > 16; the brightest 1 % - scanner
  bed / plain paper - is not used as reference, so a card on a white bed is compared with its own background),
  opening 2.5 mm (removes text / guilloche / big letters), closing 3.5 mm, portrait-shaped components 8-60 x
  10-75 mm with clearly dark parts (10th percentile < paper - 35: hair / eyes, not a tinted area), then
  `trim_to_text`. Finds the photo and the faded ghost image. Digital: embedded images with a photo shape.
  Only on ID pages by default (`fields.is_id_document`: MRZ, >= 2 identity labels, or an ID keyword).
- QR / 2D codes (`find_codes`, 100 dpi): dark modules merged by a 0.75 mm closing into a mostly solid square
  7-60 mm, density 0.3-0.75 and >= 0.45 black/white transitions per mm both ways. Digital: the page is rendered at
  150 dpi and searched the same way (image or vector codes). Signature search ignores photos, codes and the MRZ.
- Signatures: next to a label (`is_signature_label`: 'signature' / 'handtekening' / 'unterschrift' among the first
  two words of the line, or a line of <= 4 words: not a sentence); ink that is not normal-height OCR text, not a ruled line, not in the
  MRZ; seeds near the label then grows through strokes <= 3 mm apart (`_grow`), so long strokes are covered
  but a distant stamp is not. The label is spared only if the strokes do not touch it (privacy first).
  Digital: drawings / images grown the same way (frames and rules skipped), redacted with images=2, graphics=1.
- Report: `blackouts: [{page, kind, box (PDF points)}]`; Recap shows '■ 2 photos, 1 signature' and 'MRZ ...'.

## 8. Detection

Types: IBAN (mod-97 checked), BIC, EMAIL, PHONE (BE/FR/intl), CREDIT_CARD (Luhn), BE national number, BE VAT, BE structured communication,
STREET_ADDRESS (FR/NL/BE heuristics), POSTAL_CITY, ACCOUNT_NUMBER (after a label like "N° de compte" / "Numéro client", French RIB `05871 00001234567 02`, long digit runs),
BANK_CODE (after "Code banque / guichet", "Clé RIB", ...), DATE, PERSON, plus NER ORG/LOCATION.
CARD_NUMBER (masked: `6703 **** **** 4471`, `Carte x4412`; digits change, masks kept), SEPA_CREDITOR_ID
(`BE60ZZZ0404484654`, checksum-validated, or after a label like "identifiant créancier"), CONTRACT_REF (after
"police", "contrat", "dossier", ...). Page text normalises Unicode dashes (U+2010 etc.) to '-' (same length).
Masked card ends (>= 4 digits) are added as separate entries, since OCR may drop the stars.
Multi-group ACCOUNT_NUMBER / BANK_CODE values also add their groups of >= 5 digits as separate entries; digit groups are
replaced deterministically per group, so `05871` gets the same fake digits inside the account number and the bank code.
Birth dates: a DATE is active only if `_BIRTH_RX` (né le / née / naissance / geboren / birth / born / dob) appears in the
35 characters before it (or 8 after); every other date is written commented out.
PERSON heuristics (in `anonymizer/pii.py` DETECTORS): after a title (M., Mme, Dr, Mr…), `Prénom NOM`, `NOM Prénom`, plus spaCy PERSON.
`PERSON` is active by default only if: after a title, or contains a known first name, or spaCy found it in Title Case. Otherwise commented out.
Individual name parts (≥4 letters) of accepted names are added as separate entries (so a lone `Marchand` is replaced too).
NER runs line by line (page text split on newlines).

## 9. Fake values (`anonymizer/fake.py`)

Deterministic for a secret key: HMAC-SHA256(key, variant|type|value) (`anonymizer/secret.py`: 256-bit key created once
per PC in %APPDATA%\anonymizePDF\secret.key, env ANON_SECRET_FILE overrides; corrupt file -> error, never replaced).
Not reversible without the key (a constant salt in the code allowed a dictionary attack). Unique per run, same length where possible: names from FR/BE/NL name lists by length (case style kept, Title case too), keyed without accents
('Élodie' = 'elodie', so e-mails match), initials follow the replaced first name ('É. Vermeulen' -> 'S. Hendrickx'),
a name >= 80-85 % similar to one already replaced (OCR misreading) reuses its replacement,
BE national number gets the fake birth date of the same person + valid check digits, a number found inside a longer
one reuses the matching slice of its replacement (`_align_contained_numbers`), first names keep their gender (female/male lists,
else the title before the name: Mme / M., else French endings like -ette/-ine/-ie),
phones keep format and first 2 digits, IBAN keeps country/grouping with valid checksum, BIC keeps country, emails keep common domains,
streets/cities from lists by length, dates shift day/month/year, card numbers keep Luhn validity, other ids change every digit.

## 10. OCR details

Engine: `ocr.engine()` = Tesseract if found, else Windows OCR (`winrt-Windows.Media.Ocr`, languages installed with Windows,
one language at a time: first of `ocr_lang` that Windows has, e.g. fra -> fr-FR). Override: `--ocr-engine` or env `ANON_OCR_ENGINE`.
Windows OCR on the sample: ~1 s/page, accents fine, reads some 0 as O ("04 72 OO 11 22").
OCR mistakes are handled twice: `ocr.fix_digits()` repairs digit-like tokens in OCR text before detection (same length, so
spans stay valid), and on scans `term_regex(..., ocr=True)` accepts look-alikes (0/O/D, 1/l/I, 5/S, 8/B, 2/Z, missing accents,
a space inside a number). The leftover check on scans uses the tolerant regex too.
Scan replacement text: ink height measured on the original text (tight OCR boxes), same baseline, ink colour sampled,
may extend into free space like digital (`render.scan_text_layout`, `render.ink_color`).
Bold on scans (`render.BoldMeter`): median width of horizontal ink runs / font size estimated from the text, compared with
the page median (light-on-dark handled). Bold if > 1.4x. Calibrated on the sample scan vs its digital twin (764 words, 40 bold):
regular max 1.38, 1 bold word below 1.4; no false bold. Needs >= 15 measurable words on the page, else never bold.
The font family itself is not detected on scans (always Arial / Arial Bold).

Tesseract: `tesseract_words()` does two passes (default layout, then `--psm 6`). Second-pass lines are split at wide gaps (columns),
and replace first-pass words when pass 1 looks garbled (mean conf < 80 and pass 2 better by 10); if the passes disagree textually, both readings are kept.
This fixed text inside bordered boxes that psm 3 garbled.

## 12. Known limits / ideas

- ID documents: Windows OCR drops isolated letters (the 'F' of Sexe) and sometimes whole labels, so the rebuilt MRZ
  then has '<' for sex. The MRZ is only exact where the page's fields were read; otherwise right format, other
  values. An MRZ in a digital text layer is not handled yet. Bold is not detected on ID documents (most text there is bold, so no regular reference).
  Signatures need a 'Signature' label nearby; photo detection is a shape heuristic (logos with a portrait shape
  could be blacked out: `blackout.photos: false` to disable).

- Scans depend on OCR quality (handwriting, stamps, signatures missed). Names are heuristic (hence the review step).
- The leftover check only searches for values present in the config.
- Mixed digital/scan PDFs are processed as one mode per file.
- Installed fonts are looked up in the Windows registry (HKLM + HKCU Fonts, no admin), e.g. Consolas -> consola.ttf.
- Digital: replacement keeps size/colour/baseline and the font (embedded if it has the glyphs -> same font from the
  system -> closest base-14). It may extend up to +35 % to the right if nothing is there, else it is shrunk.
  Scans use a generic font. Fake names are picked by character count, not rendered width.
- Ideas: review table with checkboxes instead of raw YAML, click-to-add selected text from the viewer, highlights on the original,
  hybrid per-page mode, global mapping file across folders, batch status view, nl_core_news_md for Dutch.

## 13. Environment notes (Windows / Git Bash)

- In Git Bash use forward slashes: `source .venv/Scripts/activate`, `cd /c/Users/Lucas/Project/anonymizePDF`.
- Use `python -m pip …` if `pip` is not found.
- **Use Python 3.12 or 3.13** (`py -3.12 -m venv .venv`). Python 3.15 has no prebuilt wheels for spaCy/PyYAML and tries to compile.
- Install: `python -m pip install -r requirements.txt` then `python -m spacy download fr_core_news_md`.
- Tesseract (scans only): Windows installer with `fra`/`nld`/`eng`; auto-detected in `C:\Program Files\Tesseract-OCR` or `%LOCALAPPDATA%\Programs\Tesseract-OCR`, else set `TESSERACT_CMD`;
  `pip install tesseract` / `pytesseract` do NOT install the program (`winget install UB-Mannheim.TesseractOCR` does); set `TESSDATA_PREFIX` if languages are missing.
- `static/` must contain `index.html`, `app.js`, `style.css` (a 404 on `/` means they are not there; `app.py` now warns about it).

## 14. Rules to keep

- Never commit real PDFs, `anon_config.yaml`, `anon_report.json` or `*_anonymized.pdf` (`.gitignore` covers them; `sample_data/` is fake).

- Don't send real documents to an AI assistant; the fake sample files are enough for development.
